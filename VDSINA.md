# Публикация РЕСК на VDSina

Репозиторий: `vsementsov/resk`, ветка `main`. Сервер: SSH-алиас `vdsina`, адрес `212.193.14.81`. Домен: `реск.рф` (`xn--e1akqf.xn--p1ai`).

## Как публикуются изменения

Workflow `.github/workflows/vdsina.yml` запускается при каждом push в `main`, а также вручную через GitHub Actions. Он передаёт содержимое отслеживаемого `dist/` по SSH, проверяет опубликованный commit и завершается ошибкой, если сервер не показывает текущую версию.

Для обновления сайта соберите страницы локально, сохраните изменения и выполните push. Генерация без `--base-url` сохраняет режим согласования `noindex`; включать индексацию нужно после подтверждения содержания. Для основной индексируемой версии:

```bash
python3 tools/build_site.py --base-url https://xn--e1akqf.xn--p1ai/
```

Готовые версии находятся в `/var/www/resk/releases/`; Caddy обслуживает ссылку `/var/www/resk/current`. Переключение происходит после проверки полной загрузки. Сохраняются пять последних версий. Предпросмотры `/review-style/` исключены из Git и на сервер не передаются.

GitHub Pages остаётся отдельной ссылкой для согласования; его workflow работает параллельно.

## Доступ Actions

Используется отдельный системный пользователь `resk-deploy`. Его ключ допускает только команду приёма сайта; интерактивный shell, проброс портов и доступ root через этот ключ запрещены.

В репозитории настроены:

- секрет `VDSINA_DEPLOY_KEY` — отдельный закрытый ключ;
- секрет `VDSINA_KNOWN_HOSTS` — проверенный публичный ключ сервера;
- переменная `VDSINA_HOST` — IP сервера.

Ключи не находятся в Git. При смене сервера сначала проверьте его публичный ключ через доверенный доступ, затем обновите `VDSINA_KNOWN_HOSTS`.

## DNS и HTTPS

В DNS-панели Timeweb для корня домена (`@`) нужно изменить `A` на `212.193.14.81` и удалить старую `AAAA`, ведущую на Timeweb. Остальные записи не относятся к этой настройке. `www` пока не подключается.

До обновления DNS сайт доступен по HTTP на IP. Таймер `resk-dns.timer` раз в минуту проверяет, что домен разрешается только в IP VDSina. После этого устанавливает подготовленную HTTPS-конфигурацию и выключается. Caddy получает сертификат и затем продлевает его автоматически; команды установки и продления вручную не нужны.

```bash
ssh vdsina 'systemctl status caddy resk-dns.timer --no-pager'
ssh vdsina 'journalctl -u resk-dns.service -u caddy -n 50 --no-pager'
```

Конфигурации находятся в `/etc/caddy/sites-available/resk-https.caddy` и `/etc/caddy/sites-enabled/resk.caddy`. Исходный Caddyfile сохранён как `/etc/caddy/Caddyfile.before-resk`. Административные изменения конфигурации сервера выполняются через SSH-алиас `vdsina`; обычный push обновляет только сайт.

## Откат

Посмотрите сохранённые версии и выберите полный путь к предыдущей:

```bash
ssh vdsina 'ls -lt /var/www/resk/releases'
```

Через административный SSH создайте временную ссылку на выбранную версию и атомарно замените `current`:

```bash
ln -s /var/www/resk/releases/НУЖНАЯ_ВЕРСИЯ /var/www/resk/.rollback
mv -Tf /var/www/resk/.rollback /var/www/resk/current
```

Перезапуск Caddy для отката статических файлов не требуется. Следующий успешный push снова опубликует версию из GitHub.
