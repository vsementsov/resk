# Многостраничная версия РЕСК — локальное согласование

10 октября 2026. Многостраничная версия для согласования на GitHub Pages. Основной домен и VPS — отдельный этап.

## Структура

| URL | Задача страницы |
|---|---|
| `/` | Краткое знакомство, направления и следующий шаг |
| `/company/` | Подход, запуск сервиса, безопасность, команда |
| `/services/` | Каталог шести направлений |
| `/services/korporativnoe-pitanie/` | Питание и четыре формата обслуживания |
| `/services/gostinichnyy-servis/` | Гостиничный сервис и санатории |
| `/services/klining/` | Клининг помещений и территории |
| `/services/tekhnicheskaya-ekspluatatsiya/` | Инженерные системы и обслуживание |
| `/services/transport-i-snabzhenie/` | Перевозки и снабжение |
| `/services/servisnaya-podderzhka/` | Сопутствующие процессы |
| `/suppliers/` | Категории поставок и содержание предложения |
| `/career/` | Профессиональные направления и данные кандидата |
| `/contacts/` | Обращения и подготовка запроса |

Меню: Компания · Услуги · Поставщикам · Карьера · Контакты.
После визуальной итерации на главной три смысловых блока; подробности доступны по ссылкам.
Каждая услуга имеет собственный адрес, H1, title, description, перечень работ,
типы объектов, исходные данные для обсуждения и ссылки на смежные услуги.
Текст страниц присутствует в HTML и не зависит от исполнения JavaScript.
Относительные пути поддерживают размещение в подпапке GitHub Pages.

## Обновление

Готовые файлы находятся в `dist/`, серверу сборка не нужна.
Для повторной генерации после редактирования содержания:

```bash
python3 tools/build_site.py
```

Содержание новой архитектуры и общий шаблон — в `tools/build_site.py`.
Секции предыдущего лендинга сохранены в `content/original-landing.html`.
Стили новой версии — `dist/architecture.css`, базовые стили — `dist/style.css`.
Прямые правки HTML в `dist/` будут перезаписаны генератором.

## Локальный просмотр

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

Открыть http://127.0.0.1:8765/ .

## Индексация и публикация

По умолчанию все страницы содержат `noindex,follow`: это версия для согласования.
robots.txt разрешает обход, чтобы поисковый робот мог увидеть noindex.
Промежуточная публикация на GitHub Pages должна сохранять этот режим.

Когда подтверждены основной адрес, содержание и готовность сайта к индексации:

```bash
python3 tools/build_site.py --base-url https://xn--e1akqf.xn--p1ai/
```

Команда включает index,follow, формирует абсолютные canonical/og:url,
`sitemap.xml` и ссылку на карту сайта в `robots.txt`.
Указанный домен принадлежит пользователю, но команда не означает, что его DNS,
HTTPS или VPS уже настроены. Сначала подтвердить выбранный адрес публикации.
Для размещения в подпапке передать полный базовый URL вместе с подпапкой.
После генерации публиковать именно обновлённую `dist/`.
Дальше добавить основной сайт в Яндекс Вебмастер / Google Search Console,
проверить индексацию и настроить перенаправления со старых URL при необходимости.
SEO-основа не гарантирует позиции: понадобятся подтверждённые материалы,
данные о географии, фактические кейсы и развитие содержания под спрос.

## Что подтвердить перед основной публикацией

- Телефон, email, адрес и реквизиты компании.
- Условия сотрудничества с поставщиками и действующий канал обращений.
- Наличие вакансий, условия работы и контакт для кандидатов.
- Перечни услуг и утверждения о регламентах / качестве.
- Реальные проекты и право на публикацию материалов, если добавляются кейсы.

Фото иллюстрируют направления и не подтверждают реальные объекты РЕСК.
Изображение санатория — иллюстрация. Опыт команды относится к руководителям.
Форма скачивает локальный .txt; email и CRM не подключены.

Старые ZIP-архивы относятся к предыдущему лендингу. Для новой публикации
использовать текущую `dist/`; старые архивы пока не обновлены.

## Локальная итерация: SVG и облегчённые ресурсы

Логотип: `dist/assets/logo.svg`, исходный «FINAL — Коралловая Е» из финальных материалов проекта. Буква «Е» целиком коралловая; SVG используется в шапке и подвале всех страниц. Исходник сохранён в `content/source-assets/logo.svg`.

Значок вкладки: `dist/assets/favicon.svg` — выделенный из того же вектора фирменный знак, без белой подложки, с прозрачными уголками. Исходник сохранён рядом с логотипом.

Для всех страниц выбран плавающий белый хедер: после прокрутки появляются отступы от краёв, скругление, контур и выраженная тень. На мобильном раскрывающееся меню сохраняет ширину хедера. Адреса CSS и JS содержат версию по содержимому файла, чтобы после изменений браузер загружал актуальные ресурсы.

Карточки команды: белая поверхность, тонкий тёмно-синий контур, скругление 18 px и мягкая двухслойная тень. Декоративные коралловые точки удалены. Показатели опыта оформлены без вложенной карточки; от описания их отделяет одна тонкая линия. Проверено на мобильном и большом экране.
Исходные растровые ресурсы и шрифты сохранены в `content/source-assets/`.
Повторная подготовка ресурсов: `python3 tools/optimize_assets.py`, затем `python3 tools/build_site.py`.
Для генерации локально используются Pillow и fontTools; при публикации серверу нужны только готовые файлы `dist/`.
Фотографии имеют WebP-версии для небольших экранов, HTML использует `srcset`/`sizes` и реальные размеры. Карточки используют небольшие изображения.
Шрифты содержат кириллицу, латиницу и используемые знаки; упакованы в WOFF с `font-display:swap`. При добавлении других алфавитов расширить набор символов в оптимизаторе.
Хедер получает мягкую тень после прокрутки; мобильное меню окрашено в #CC4751.
Декор финальных блоков закреплён справа снизу отдельным слоем с постоянными пропорциями.
Карточки команды имеют единый тонкий контур, мягкую тень, панель опыта и коралловую точку.
Изменения этой итерации пока локальные, push не выполнялся.
# Локальное сравнение оформления

`python3 tools/preview_styles.py` создаёт `/review-style/` с двумя вариантами хедера при прокрутке и карточек команды. Предпросмотры собираются из текущей страницы компании; в обоих вариантах показатели опыта оформлены без вложенного контейнера. Каталог предпросмотров исключён из Git и не публикуется в Pages. После изменения страницы компании предпросмотры нужно собрать повторно.

В основной версии фон завершающих блоков занимает полную ширину и высоту секции; размеры декоративного слоя совпадают с размерами блока. Проверены ширины 390, 725, 1366 и 1920 px.


## Превью ссылок в мессенджерах

На всех страницах есть Open Graph и Twitter Card: название и описание страницы,
её публичный URL, название РЕСК, язык и картинка с логотипом. По умолчанию URL
превью ведут на `https://xn--e1akqf.xn--p1ai/`; это отдельно от настройки индексации.
`--share-base-url https://другой-домен/` меняет адреса превью без включения SEO.
При сборке с `--base-url` этот адрес используется и для превью.

Картинка `dist/assets/social-preview.jpg` — JPEG 1200×630, около 58 КБ.
Её SVG-исходник — `content/source-assets/social-preview.svg`.
После изменения логотипа повторить:

```bash
python3 tools/build_social_preview.py
python3 tools/build_site.py
```

Генератор картинки использует фирменный SVG и шрифт Noto; зависимости —
fontTools, Pillow и команда `rsvg-convert` (пакет `librsvg2-bin` в Ubuntu).
В адрес изображения добавляется хеш содержимого для обновления кеша картинки.
Кеш самой карточки ссылки обслуживается мессенджером, поэтому существующие
сообщения могут сохранить старое превью после публикации.
